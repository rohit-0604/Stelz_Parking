# Localized marketing content

English source files remain unchanged in `/data`. Each locale file owns one strongly typed `MarketingCopy` pack and exports the complete localized content generated by `factory.ts`. Structural identifiers, asset paths, brochure URLs, categories, and canonical English slugs are copied from the English source automatically.

- `de.ts` — German
- `ar.ts` — Arabic
- `hi.ts` — Hindi
- `zh-hant.ts` — Traditional Chinese
- `ko.ts` — Korean
- `ja.ts` — Japanese

Shared interface text, navigation labels, metadata, form labels, and accessibility labels live in `/data/i18n/messages.ts`. URL translations live in `/lib/i18n/routing.ts`.

To add a language, add it to `lib/i18n/config.ts`, add its route-segment map in `lib/i18n/routing.ts`, create a locale marketing pack here, and add its interface messages in `data/i18n/messages.ts`. TypeScript checks every required marketing section and fixed-size content group.

For products, edit only the translated names, shared descriptions, features, applications, and SEO phrases in the locale pack. Never translate `id`, `category`, `slug`, `path`, asset paths, or brochure paths. The routing layer translates visible URLs independently.

The factory intentionally produces complete locale-owned content rather than silently falling back to English body copy. Proper names, model codes, addresses, URLs, and registered brand names remain unchanged.

Example:

```ts
const copy = {
  // Complete MarketingCopy pack for this locale.
} satisfies MarketingCopy;

export const overrides = createLocalizedContent(copy);
```

Intentional localization, globalization, accessibility, functionality, and mobile defects are distributed across the real routes. Their instructor-only catalogue lives in `docs/INSTRUCTOR_GUIDE.md`.
